## 3. 投影片瀏覽（揭曉畫廊，`features/reveal/`）

PowerPoint「投影片瀏覽」檢視：工作區灰底，投影片縮圖以網格排列，**每位參賽者一張**。

```
┌────────────────────────────────────────────────────────┐
│  ① Alice  87 分     ② Bob  74 分     ③ Carol  61 分       │
│  ┌──────────┐      ┌──────────┐      ┌──────────┐       │
│  │  (畫)    │      │  (畫)    │      │  (畫)    │       │
│  └──────────┘      └──────────┘      └──────────┘       │
│  ④ Dave  40 分      ⑤ Eve  未儲存                        │
│  ┌──────────┐      ┌──────────┐                         │
│  │  (畫)    │      │  （空白） │                         │
│  └──────────┘      └──────────┘                         │
└────────────────────────────────────────────────────────┘
```

- **參考圖卡（Epic 20，mimic 回合）**：網格第一格，標題列「參考圖」、無名次編號、無分數、無評語行；縮圖為參考圖 JPEG（16:9 內 `object-fit: contain`、`--bg-editor` 底）、可放大；不在 `results` 內；按鈕 aria-label「參考圖（放大）」、放大時「參考圖（回到全部）」，**用 `data-reveal-reference` 而不是 `data-reveal`**（事務長技能以 `button[data-reveal]` 讀名次卡，參考圖卡不得混入；2026-10-26 定案）。
- 排序＝`results` 的 `rank`。縮圖 16:9、白框 1px `--border`、陰影同投影片；前三名外框 2px `--accent`，名次以投影片編號位置顯示「①②③」（其餘用數字）；自己的那張底 `--bg-active`。
- 前三名外框只給有交卷者。標題列文字：名次、暱稱、分數（`tabular-nums`）；`judgedBy === 'random'` 時分數後加小字「隨機」；未交卷顯示「未儲存」與空白投影片。
- **評語行（Epic 15）**：**縮圖下方**一行（2026-10-12 定案由「標題列下方」改到縮圖下方：同一列卡片評語行數不同時縮圖上緣才對得齊；卡片底部高度隨評語行數變化），`COMMENT_PERSONA_NAME`（2026-10-21 起為 `ミオ`，原 `メスガキ`；Rex 2026-10-21 不要這個詞、選了名字 ミオ）粗體 `--fg` 作前綴、冒號後接評語，12px 斜體 `--fg-muted`、**不截斷**（2026-10-12 定案移除 `line-clamp-2`：40 字在 220px 欄約 2～3 行，截斷的「…」與產生中的「…」目視分不出來；卡片高度隨行數變化，縮圖已對齊不受影響）；`commentPending` 時顯示「{COMMENT_PERSONA_NAME}：正在寫評語」（現為「ミオ：正在寫評語」）（**不用省略號**，與截斷區分；2026-10-12 定案）；`comment === null` 且不 pending（未交卷、失敗、`commentMode 'off'`）不顯示該行，卡片高度隨之縮短——**只看卡片自身欄位，不看 `commentMode`**（回合中途失敗時已產生的評語照常顯示）。放大檢視的完整句**同樣放圖片下方**（不 clamp；2026-10-12 定案與網格卡片一致）。網格評語行上方間距 6px。偽裝語意＝投影片的「註解」，但功能元件不寫死偽裝字樣，前綴用評審名稱即可。
- 點縮圖：放大顯示在中央（同「普通檢視」投影片尺寸），再點或 Esc 回網格。Phase 2 可選。
- 寬度：縮圖欄 `repeat(auto-fill, minmax(220px, 1fr))`，間距 16px；< 768px 兩欄。
- 畫廊圖片來自 `contest:gallery` 的 object URL；收不到（極端）顯示灰底「載入中」。

### 3.1 歷史檢視（Epic 17，`features/history/`）

- **入口**：「檔案」選單加一項「開啟最近的簡報 ›」，子清單最多 5 列（最新在上）：「{題目} — {月/日 時:分} — 第一名 {暱稱}（{分}）」；沒有存檔時灰字「沒有最近的簡報」（`aria-disabled`）。`drawing`／`judging` 中或自己是出題者時整項灰化。殼層開啟「檔案」選單時呼叫 `history.refresh()` 重讀清單。
- **檢視**：中央投影片區以 §3 的網格顯示存檔的畫、名次、分數、評語（Epic 20：存檔含 `reference` 時第一格為參考圖卡）（評語行只在有評語時顯示，沒有「正在寫評語」）；自己當時那張（存檔的 `me`）照 §3 標示；左上無額外標籤；放大檢視沿用。備忘稿列文案見 §2 表。狀態列中段放「關閉簡報」按鈕（殼層自己渲染，點擊呼叫 `history.close()`）。
- **自動關閉**：`drawing` 開始、直接看到 `judging`、`roundNo` 變了、離開遊戲，或自己成為出題者時關閉並回到目前畫面；關閉時 revoke 存檔圖片的 object URL。檢視中狀態列中段是「關閉簡報」、沒有「我出題」，所以要出題得先關閉簡報（「自己成為出題者」只在 store 層成立，驗收 2026-10-13 觀察）。
- **只存瀏覽器**：IndexedDB `fishing-work:draw-contest` / `history`，最近 5 場，超過刪最舊；不經 server、不分暱稱；IndexedDB 不可用時入口顯示「沒有最近的簡報」。

## 4. 響應式與可及性

沿用 DESIGN §8、§9 與 §13.3。工具列收合斷點 **540px**（帆 2026-10-07 實測：完整工具列加「完成」在 518px 開始溢出，留餘裕定 540）；「完成」是獨立插槽 `finish`，固定在功能區右端、不在捲動區內，任何寬度都看得到。已知限制：375px 時右側註解窗格佔約一半寬度、備忘稿列被截斷（繼承自 ppt 版面；手機為範圍外，只記錄不修）。「完成」確認框、投影片瀏覽的縮圖皆可鍵盤操作。
