# 區網實機實測清單（我畫你猜）

> 給 Rex 照著做：用兩台以上**實體裝置**經公司區網玩完一回合，對應 [plan/draw-guess-mvp.md](../plan/draw-guess-mvp.md)「驗收標準」的區網那條（出題、畫、猜對、揭曉、計分）與「中途加入者能看到既有筆跡與最近聊天」。
> 部署步驟以根目錄 [README.md](../README.md)「正式部署（區網）」為準，本檔只列實測步驟與勾選項。
> 自動化的 30／50 人壓測已由 `user/protocol/draw-guess-load.mjs` 在本機跑過；本清單驗的是**真實網路與真實瀏覽器**。

## 準備

| 角色 | 裝置 | 用途 |
|------|------|------|
| 主機 | Rex 的 Mac | 跑 `npm start`；同時開一個瀏覽器分頁當玩家 A |
| 玩家 B | 同事筆電（或 Rex 的第二台裝置） | 畫師 |
| 玩家 C | 手機或另一台筆電 | 中途加入、F5 重連 |

- [ ] 所有裝置連同一個公司網路（不是訪客 Wi-Fi、沒開會分流的 VPN）
- [ ] 主機上沒有 `npm run dev` 在跑（`lsof -nP -iTCP:80` 沒有輸出，或只有你要關掉的那個）

## 1. 啟動與連線

- [ ] 主機：`npm run build` 成功（exit 0）
- [ ] 主機：`caffeinate -i npm start`（或在 tmux 裡跑），log 出現 `server.listen`（`port` 為 80）
- [ ] log 的 `server.lan` 列出區網網址，記下：`http://______________/draw-guess/`
- [ ] 若 macOS 跳出「是否允許 node 接受連入連線」→ 允許
- [ ] 玩家 B 裝置開 `http://<IP>/healthz` → 顯示 `{"ok":true}`
- [ ] 玩家 B 裝置開 `http://<IP>/` → 看到遊戲清單「我畫你猜」
- [ ] （選做）玩家 B 開 `http://<電腦名稱>.local/healthz` 也能通（`scutil --get LocalHostName` 查名稱）

## 2. 加入

- [ ] A（主機分頁）與 B 開 `http://<IP>/draw-guess/`，畫面像程式編輯器、上方有暱稱輸入框
- [ ] A、B 以不同暱稱加入，左側 EXPLORER 兩邊都看到對方的 `<暱稱>.ts`
- [ ] B 試著用 A 的暱稱（大小寫不同也算）加入 → 被拒並顯示錯誤（驗完改回自己的暱稱）
- [ ] 底部 TERMINAL 出現「X 加入」

## 3. 一回合（B 當畫師）

- [ ] B 按狀態列「▷ 我來畫」→ 上方出現出題輸入框；A 的狀態列顯示有人在出題
- [ ] B 出題（例如「長頸鹿」）→ B 看得到題目，A 只看到字數提示 `＿ ＿ ＿`
- [ ] B 畫幾筆（換顏色、換粗細、用一次橡皮擦）→ A 即時看到，**延遲肉眼無感**（B 畫的同時看 A 的螢幕，筆跡幾乎同步出現）
- [ ] B 按「復原」→ A 的最後一筆消失；B 再畫幾筆
- [ ] A 在 TERMINAL 打錯的答案（例如「馬」）→ 所有人看到這則訊息
- [ ] A 打「是長頸鹿嗎」→ 被擋下、提示只輸入答案本身，B 看不到
- [ ] B 在 TERMINAL 打含題目的訊息 → 被擋下，A 看不到

### 中途加入（C）

- [ ] 作畫進行中，C 開 `http://<IP>/draw-guess/` 以新暱稱加入
- [ ] C 一進來就看到**目前畫布上的既有筆跡**（包含 B 復原後的狀態，不會出現被復原的那筆）
- [ ] C 的 TERMINAL 看得到**最近的聊天**（A 猜錯的那則、「X 加入」等）
- [ ] B 繼續畫，C 也即時看到

### F5 重連（C）

- [ ] C 先猜對（打「長頸鹿」）→ 所有人看到「C 猜對了」，C 的原文不出現；C 的分數變成 50～100
- [ ] C 按 F5 重新整理 → **不用重打暱稱**自動回到遊戲，分數與「已猜對」標記仍在，畫布筆跡還在
- [ ] 重新整理期間，其他人的 EXPLORER 上 C 短暫變淡（斷線中），回來後恢復

### 猜對、揭曉、計分

- [ ] A 打「長頸鹿」（試試「 長頸鹿 」前後加空白也算）→ 全員猜對，回合結束
- [ ] 所有人的 TERMINAL 出現「題目是 長頸鹿（全員猜對）」
- [ ] 分數：A、C 各 50～100（越快越高）；B（畫師）+40（每人猜對 +20）；三台裝置看到的分數一致
- [ ] 約 5 秒後回到等待狀態，畫布保留到下一回合開始
- [ ] （選做）換 A 當畫師再玩一回合，這次由 A 按「放棄」→ 揭曉「題目是 X（畫師取消）」

## 4. 收尾

- [ ] 主機終端機按 `Ctrl+C` → log 出現 `server.shutdown`，各裝置顯示重新連線中
- [ ] `lsof -nP -iTCP:80` 沒有殘留程序

## 出問題時要收集的資訊

請把以下內容一併回報（貼文字或截圖），比較好判斷是網路、防火牆還是程式問題：

1. **狀況描述**：哪一台裝置、做了什麼、預期看到什麼、實際看到什麼、大約幾點幾分。
2. **server log**（主機終端機，一行一筆 JSON）：
   - 啟動時的 `server.listen`、`server.lan`（或 `server.lan.none`、`server.listen.failed` 與其 `hint`）
   - 出問題前後的 `draw-guess.connect`、`draw-guess.join`（`addr` 是對方 IP，可確認對方到底有沒有連進來）、`draw-guess.join.rejected`（`error` 欄位）、`draw-guess.disconnect`（`reason` 欄位）
   - 任何 `"level":"warn"` 或 `"level":"error"` 的行
   - 若筆跡不同步：有沒有 `draw-guess.draw.dropped`（被丟棄的筆跡）
3. **瀏覽器 console**（出問題的那台）：
   - 桌機 Chrome／Edge：`F12` 或 `Cmd+Option+J` → Console 分頁，紅字錯誤全部截圖
   - Safari：先在「設定 → 進階」勾選顯示開發選單，再 `Cmd+Option+C`
   - 手機：看不到 console 時，記下畫面上的錯誤文字與狀態列的連線狀態即可
   - Network 分頁的 `socket.io` 請求狀態（是 101 WebSocket、還是一直重試）
4. **網路資訊**：主機 `ipconfig getifaddr en0` 的結果、出問題裝置的 IP（同一網段嗎？例如都是 `192.168.1.x`）、對方開 `http://<IP>/healthz` 的結果。
